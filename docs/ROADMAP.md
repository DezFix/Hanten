# Roadmap: чего не хватает Hanten

Дата: 2026-11-02. Основано на коде `2.4.3` и сравнении с типичным набором
manga-reader'ов: Mihon/Tachiyomi, Kotatsu, Komikku, Panels, Suwayomi/Tachidesk,
Mangayomi, Paperback, Komga/Kavita (серверы).

> Цель Hanten — не догнать все фичи всех форков, а закрыть то, что реально
> мешает людям пользоваться библиотекой каждый день: перенос данных,
> сохранность библиотеки, нормальные трекеры и чтение без сюрпризов.
>
> Отдельное ограничение: **парсеры — только RU/UK**. Остальные языки
> в `hanten-parsers` не развиваем и не изучаем; новые источники — только
> русские и украинские.

---

## 1. Что уже хорошо

Hanten уже сильнее среднего форка по этим пунктам:

- **RU/UK-источники** и приоритетная их починка;
- **Mihon/Tachiyomi-расширения** (редкость для Kotatsu-форков);
- **загрузки**: очередь, пауза, Wi-Fi/зарядка/off-peak, квота, smart download;
- **трекеры**: Shikimori, AniList, MAL, импорт/экспорт Shikimori;
- **бэкапы**: секционные zip, периодические, Telegram своим ботом;
- **статистика**, лента обновлений, рекомендации;
- **ридер**: webtoon/vertical/reversed/double-page, foldable, pull-to-chapter,
  auto-scroll, кроп, цветокоррекция;
- **приватность**: incognito, app lock, свои OAuth-приложения;
- **UI**: Material You, планшеты, виджеты, шорткаты, QR-шаринг.

Поэтому roadmap ниже — не «добавить всё», а закрыть дыры.

## 3. Предложения по приоритетам

### P0. Сначала — доверие и сохранность данных

#### 3.1. Починить и закрыть P0 из `CODE_REVIEW.md`

Без этого новые фичи опасны: импорт Shikimori не работает, auto-backup
падает, Telegram-токен утекает в бэкап, sync-серверы чужие, расширения
без проверки подписи.

Оценка: 1–3 дня. Эффект: больше, чем от любой новой фичи.

#### 3.2. Шифрованные бэкапы

Сейчас zip читается любым, у кого есть файл. Предложение:

- опциональный пароль на бэкап (AES-256, например `zip4j` или
  `androidx.security` + потоковое шифрование);
- предупреждение, если бэкап с токенами/паролями;
- отдельный «safe backup» без секретов.

Оценка: 2–4 дня. Риск: совместимость со старыми бэкапами (оставить
чтение старых, писать новый формат с версией).

#### 3.3. Секреты — в Keystore, а не в prefs

- Telegram bot token, OAuth refresh/access tokens, пароль приложения.
- `EncryptedSharedPreferences` или собственный Keystore-ключ.
- Исключить `cookies`, `scrobbler prefs`, `backup_periodic_tg_*` из
  Android cloud backup.
- Добавить secret-scan в CI (`gitleaks`/`trufflehog`) и проверку APK.

Оценка: 2–5 дней. Риск: миграция старых токенов (одноразово прочитать
и перезаписать).

---

### P1. Перенос данных и sync

#### 3.4. Импорт `.tachibk` / Mihon backup

Самая частая причина, почему человек не переходит на форк: «а как перенести
300 тайтлов?». Предложение:

- читать protobuf-бэкап Mihon/Tachiyomi (у Hanten уже есть
  `mihon/parsers/model` и protobuf-зависимость);
- маппить source name → локальный `MangaSource` (parser или Mihon extension);
- импортировать категории, историю, трекеры, настройки (по секциям);
- показывать отчёт: импортировано / не найден источник / дубликат;
- экспорт в простой JSON/CSV и, по возможности, `.tachibk`.

Оценка: 5–10 дней. Риск: разные версии формата, source ID не совпадают.
Выгода: максимальная для миграции.

#### 3.5. Sync: свой backend или честно убрать

Сейчас код sync есть, но `is_sync_enabled=false`, а дефолтные серверы —
чужие. Варианты:

1. **Свой минимальный сервер** (Ktor/Go + Postgres/SQLite) с E2E-шифрованием
   библиотеки/истории; клиент уже есть (`SyncAdapter`).
2. **WebDAV/Nextcloud** как транспорт без своего сервера: проще, но
   конфликты решать сложнее.
3. **Только файловый sync** (папка/облако) с merge-политикой.

Оценка: 2–6 недель для нормального сервера. Риск: поддержка, приватность,
стоимость. Пока сервера нет — убрать обещание из README.

#### 3.6. Облачные бэкапы

Добавить адаптеры хранения:

- Google Drive App Folder (Drive API, OAuth);
- WebDAV (Nextcloud, Yandex Disk через WebDAV);
- S3-совместимое (MinIO/Backblaze) — опционально.

Периодический бэкап уже есть; не хватает только `ExternalBackupStorage`
на новый backend и настройки.

Оценка: 5–10 дней на адаптер. Риск: OAuth-верификация Google, лимиты.

### P1. Источники и расширения

#### 3.7. Проверка подписи и нормальный менеджер расширений

- Подключить `InstalledExtensionSignatureValidator`.
- Показывать «непроверенное расширение» и не грузить его без явного
  подтверждения.
- Проверять `libVersion` сверху и снизу.
- Кнопка «обновить все», список репозиториев, откат версии.
- Кэш метаданных, чтобы не сканировать все пакеты на каждом старте.

Оценка: 3–7 дней. Это и безопасность, и UX.

#### 3.8. OPDS / Komga / Kavita / Suwayomi

Для self-hosted пользователей:

- OPDS 1.2/2.0 как read-only источник (каталог, поиск, страницы);
- Komga/Kavita — через OPDS или их REST API;
- Suwayomi/Tachidesk — как источник с собственной библиотекой.

Оценка: 1–2 недели на OPDS, ещё столько же на REST-адаптеры.
Риск: разные диалекты OPDS. Выгода: целый сегмент пользователей.

#### 3.9. Метаданные для локальной библиотеки

- Читать/писать `ComicInfo.xml` в CBZ/папках (title, series, volume,
  summary, tags, page count).
- Поддержать `.nomedia`, чтобы галерея не показывала страницы.
- Экспорт обложек/метаданных для Komga/Kavita.

Оценка: 3–5 дней. Хорошо сочетается с OPDS.

---

### P2. Трекеры и библиотека

#### 3.10. Больше трекеров и импорт/экспорт

- **Bangumi** — популярен для CN/части RU-аудитории.
- **MangaUpdates** — англоязычные тайтлы.
- **Anime-Planet** — если есть API.
- Импорт/экспорт библиотеки для **MAL** и **AniList** (как сейчас для
  Shikimori).
- Двусторонняя синхронизация статуса/оценки/комментария, обработка
  конфликтов.

Оценка: 3–7 дней на сервис. Риск: OAuth/лимиты/нестабильные API.

#### 3.11. Пакетная работа с библиотекой

- Выделить несколько тайтлов → добавить/убрать категории, теги, статус.
- Отметить «прочитано/не прочитано» пачкой.
- Найти дубли (одинаковый title/altTitle/author) и слить/смигрировать.
- Массовая миграция на другой источник с сохранением истории.
- Уже есть saved filters и actions — расширить на multi-select.

Оценка: 5–10 дней. Риск: случайные массовые удаления (нужен undo).

#### 3.12. Импорт из URL/списков

- Вставить список ссылок (MAL/Shikimori/текст) → найти в источниках.
- Импорт категории из Shikimori уже есть; обобщить на CSV/JSON.

Оценка: 3–5 дней.

---

### P2. Ридер

#### 3.13. Page curl / split wide pages / panel view

- Анимация перелистывания (опционально, не ломать 60 fps).
- Автоматическое разбиение широких разворотов на две страницы.
- Кроп по сторонам (сейчас общий crop).
- Panel-by-panel для вебтунов — сложно, но заметная фича у некоторых
  ридеров.

Оценка: 1–3 недели. Риск: производительность на слабых устройствах.

#### 3.14. TTS и доступность

- Озвучка текста (Android TTS) для новелл/комиксов с OCR — тяжело.
- Для начала: TalkBack-метки, масштаб шрифта, контраст, reduced motion.
- Горячие клавиши для Chromebook/планшета с клавиатурой.

Оценка: TTS — 2–4 недели, доступность — 3–5 дней.

---

### P3. Платформа и мелочи

#### 3.15. Android TV / Chromebook

- Leanback-манифест, D-pad-навигация, баннер.
- Отдельная сетка и пульт-управление.
Оценка: 2–4 недели. Низкий приоритет, пока нет запроса.

#### 3.16. Уведомления и обновления

- Настройка «только избранные источники/категории».
- Тихие часы.
- Группировка по тайтлу, а не по главе.
- Быстрый переход к первой новой главе.

Оценка: 2–4 дня.

#### 3.17. Загрузки

- Повтор конкретной главы, а не всей манги.
- Понятный экран «очередь/ошибки/история».
- Оценка свободного места и «сколько займёт».
- Экспорт в PDF/EPUB (спорно, но просят).

Оценка: 3–7 дней.

## 4. Что не стоит добавлять

- **Соцсеть/комментарии/ленту друзей** — нужен backend и модерация,
  не вписывается в «читалку».
- **Свой VPN/прокси-сервис** — юридические и эксплуатационные риски.
- **Torrent-источники** — безопасность и правовые риски.
- **AI-рекомендации на сервере** — дорого, приватность, нет данных.
- **Ещё одну ORM/архитектуру** — Hilt+Room+Flow уже достаточно.
- **Ещё один форк парсеров** — лучше чинить `hanten-parsers`.

## 6. Метрики, по которым проверять решения

- Время до первого чтения после установки (onboarding + источники).
- Доля успешных импортов библиотеки.
- Crash-free sessions и число ошибок источников.
- Время проверки 100 тайтлов трекером.
- Размер APK и время холодного старта.
- Количество обращений «не работает источник» на 1000 установок.
- Доля пользователей с включёнными бэкапами (локально/облако).
